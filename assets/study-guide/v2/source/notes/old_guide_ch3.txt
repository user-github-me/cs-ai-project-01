MIDDAY  ·  Hardware
Hardware gives software a body
Classify by the job being performed
Hardware is the physical part of a computer system. An input device supplies data, a processing
device transforms it, an output device communicates or acts on a result, and storage retains
information. One device can have several roles: a touchscreen displays output and senses input. A
barcode reader is input; an SSD is storage.
From a physical event to a response
Sensor / input
Processor + memory
Output / actuator
The processor follows instructions. Useful behaviour depends on the program, the data, the hardware and
their connections.
How hardware enables AI
An AI model must run as computations on hardware. Sensors provide observations, memory holds
model parameters and working data, a processor evaluates the model, and an output device
communicates the decision. A physical robot also needs a powered actuator to move. More
powerful hardware can increase capacity or speed, but does not itself create a learning algorithm.

Memory: capacity versus speed
A useful hierarchy
Resource
Role and trade-off
Registers
Very small, very fast storage inside the processor.
Cache
Fast memory holding copies of recently or frequently used data.
Main RAM
Working storage for active programs and data; normally volatile.
Secondary storage
Larger, persistent storage; usually slower to access.
SRAM and DRAM
Static RAM stores bits using bistable circuits such as flip-flops. It needs power but no periodic
refresh, and is commonly used for CPU caches. Dynamic RAM stores charge in cells that must be
refreshed; its greater density and lower cost make it suitable for main memory. Both are volatile.
Cache can be on the processor chip; it is not necessarily external.
Why an AI workload needs memory
Model weights, input data and intermediate results must fit somewhere. A fast processor can
spend time waiting for data if memory bandwidth is insufficient. Capacity answers “how much
fits?” Bandwidth answers “how quickly can it move?” These are different constraints and both
affect performance.

ROM and flash families
Type

Electrically erasable and reprogrammable.
Flash
Electrically erasable memory, normally erased in blocks.
Magnetic, solid-state and optical media
A hard disk stores data magnetically on rotating platters. Seek time and rotational latency delay
access; fragmentation can increase head movement. An SSD stores data in flash with no moving
parts. It avoids mechanical seek and rotation delays, but still has nonzero access latency and finite
write endurance. External drives can provide portable backup storage.
Optical storage
CDs, DVDs and Blu-ray discs use laser light to read recorded features. Some discs have multiple
recording layers. Material defects and optical effects, including birefringence, can disrupt reading.
Choose a medium using capacity, access time, cost, durability and the need for long-term
retention rather than assuming one technology is best for every purpose.

The distinction is not a speed guarantee
A reduced instruction set does not guarantee that every instruction takes one clock cycle. A
complex instruction set does not prevent pipelining or high performance. Modern processors use
caches, pipelines, prediction and other techniques; many translate instructions internally into
simpler operations. Some RISC families also support compressed instruction encodings.
Look at the workload
Performance depends on implementation, clock frequency, instructions per cycle, memory
behaviour, software and energy constraints. A mobile device may prioritise power efficiency; a
workstation may prioritise throughput. Compare measured work done under relevant conditions
instead of judging a CPU from the RISC or CISC label alone.

Overlap work with a pipeline
Use the laundry analogy
A laundry can wash one load while drying an earlier load. Similarly, a processor pipeline can fetch
a new instruction while decoding or executing previous ones. This increases throughput after the
pipeline fills; it does not necessarily reduce the latency of an individual instruction. Pipelining is
used in both RISC and CISC implementations.

Why a pipeline can pause
A data hazard occurs when an instruction needs a result that is not ready. A control hazard occurs
when a branch makes the next instruction uncertain. A structural hazard occurs when operations
need the same resource. Stalling, forwarding, scheduling and prediction can help, depending on
the processor. “Overlapping” does not mean every instruction is independent.

Scale beyond one processor
A cluster connects computers, called nodes, so they can coordinate work. Massively parallel
systems distribute large tasks across many processing units. Supercomputers are designed for
demanding scientific or engineering computation; they are not simply a synonym for mainframes.
Communication, synchronisation and data movement affect whether adding processors actually
helps.
Connect this to AI
Large arrays of multiplications can benefit from parallel hardware. Parts of an AI workload may still
be sequential or limited by memory and communication. A GPU has its own execution model,
often described using SIMT, and provides SIMD-like parallel arithmetic; the simple taxonomy is a
starting point, not a complete description of every chip.

Let hardware request attention
Events can change the schedule
A sensor, network interface or timer can raise an interrupt. The CPU responds when the request is
enabled and eligible. It preserves enough context to resume the interrupted work and transfers
execution to a handler. The handler deals with the event and returns. The hardware and operating
system divide the responsibility for saving and restoring state.
A simplified service sequence
Event arrives
Preserve context
Run handler
Resume task
Context can include the program counter, status and required registers. Exact details vary by architecture.
Predictability matters
A system with a timing deadline must account for interrupt priority, handler execution time and
other sources of delay. RISC versus CISC alone does not determine interrupt latency. Long or
frequent interrupt handling can delay useful work. A well-designed system measures worst-case
behaviour rather than assuming every event will receive an immediate response.

Read symbols and conditions
NOT maps 0 to 1 and 1 to 0. An AND symbol has a flat input side and curved output side; an OR

A worked simplification
Let X = (A AND B) OR (A AND NOT B). Factor out A: X = A AND (B OR NOT B). The term in
brackets is always 1, so X = A AND 1 = A. A simpler equivalent circuit can reduce hardware and
delay. Check equivalence by comparing truth-table outputs for every input combination.
Keep the negation in the right place
De Morgan’s laws negate the whole grouped expression on the left. Dropping that outer NOT
changes the meaning. Parentheses make the scope clear, especially when a printed overbar is
difficult to see. In Boolean algebra, OR is not ordinary arithmetic addition: 1 OR 1 is still 1.

Sense, decide, act, sense again
Monitoring versus control
A monitoring system records or displays measurements. A control system also acts on the
environment. In a greenhouse, a temperature sensor supplies a reading, a processor compares it
with a target, and a fan changes the temperature. A later measurement closes the feedback loop.
This can be a fixed-rule controller; learning is not required.
An environmental control loop
Sensor
Input conversion
Decision
Driver + actuator
The changed environment is measured again. Analogue sensors may need an ADC; many sensors already
provide digital data.
Signals are not actuator power
An ADC converts an analogue signal to a digital value. A DAC converts a digital value to an
analogue signal. Some actuators use PWM or digital interfaces instead of a DAC. PWM is a timed
switching signal, not the same thing as analogue conversion. A motor driver or power stage
supplies the current needed to move a motor or operate a valve.

Different processing strengths
Hardware
Useful role
CPU
General control, branching and diverse program tasks.
GPU

Specialised tensor operations with hardware-specific efficiency.
RAM and storage

Training and inference have different costs
Training adjusts model parameters using data or experience. Inference uses a model to produce
an output. A model may be trained on a large server and deployed on a smaller device. Simple
tabular reinforcement learning can run on an ordinary CPU; AI does not always require a GPU, and
a specialised chip is not automatically faster for every workload.
Trace the whole path
For a camera-based robot, the sensor captures an image, memory buffers it, processing estimates
a useful state, a policy selects an action, and control hardware drives the actuator. Delays in any
stage matter. Model size, memory movement, power consumption and heat can be as important
as the advertised arithmetic speed of the chip.

Display quality involves trade-offs
Screen resolution describes pixel dimensions. OLED can provide deep blacks because individual
pixels can be off, but power use depends on displayed content and hardware. Capacitive and
