Connect a room, a city, a world
What a network provides
A network connects devices so they can exchange data and share services, storage or hardware. A
connected device is a node. Networks differ in scale, ownership, transmission media and
management. Geographic size alone does not determine speed: a particular WAN link can be
faster than a particular local wireless connection.
Names describe the scope
Network
Typical scope
PAN / WPAN
A person’s nearby devices; a WPAN is wireless.
LAN / WLAN
A home, office or building; a WLAN uses wireless links.
MAN
A metropolitan area or several sites across a city.
WAN
Widely separated sites, regions or countries.
A practical analogy
A personal conversation resembles a PAN, a building intercom resembles a LAN, and an inter-city
transport network resembles a WAN. Real networks can contain smaller networks inside them. The
Internet is a global interconnection of networks, built from links and equipment operated by many
organisations.

Public and private clouds
A public cloud provides services using infrastructure operated by a provider for multiple
customers. A private cloud is dedicated to one organisation and can be on-site or hosted
elsewhere. Public cloud can reduce initial capital cost and offer flexible capacity; private cloud can
provide greater direct control but requires resources to manage.
Compare actual responsibilities
Neither deployment is automatically secure. Consider access control, configuration, backups, data
location, operational expertise and ongoing cost. Replication improves availability but is not a
substitute for a recoverable backup. A thin client still performs some local processing, such as
displaying an interface; “thin” does not mean it has no CPU.

Addresses serve different scopes
An Ethernet switch learns which MAC addresses are reachable through which ports. A router uses
IP routing information to select a next hop. MAC addresses can be changed or randomised; they
are not always permanently fixed identifiers. A modem’s modulation depends on the medium,
rather than being limited to old telephone lines.
A switch is selective, not omniscient
Known unicast frames can be sent to a selected port. Broadcasts and unknown destinations may
be flooded within the relevant LAN. A router chooses a route using its routing table and policies;
it does not always measure the least congested possible path for every packet.

The web is one Internet service
The Internet carries many kinds of communication. The World Wide Web uses linked resources
accessed through web protocols. Email and other services also use the Internet. IPv4 addresses
have 32 bits; IPv6 addresses have 128 bits. An address helps identify a network interface for
communication, while routing determines how packets are forwarded.

Find a host with DNS
Names are easier to remember
The Domain Name System maps names to records, including records that provide IP addresses. A
browser and operating system may already have a cached answer. If not, a recursive resolver can
obtain an answer using the DNS hierarchy. Cached answers remain usable for their permitted
lifetime, reducing repeat lookups.
A simplified lookup
Client
Recursive resolver
Root / TLD
Authoritative server
The resolver follows referrals, receives the requested record, caches it and returns the answer to the client.
The lookup is only one step
After resolving a host, a client still needs to establish suitable communication with the service.
DNS does not deliver the web page itself, and it does not translate an entire URL, including its
path, into an address. Failures in DNS, connectivity, transport, security negotiation or the
application can each prevent a page from loading.

Encapsulation is packaging
Application data is carried inside transport data, which is carried inside IP packets, which are
carried by link-layer frames. Each layer has its own fields and scope. A frame’s MAC addresses are
not the same thing as an IP packet’s addresses; the frame can change at the next link while the
packet continues its journey.
Reliable ordering is a service choice
TCP provides an ordered byte stream with reliability and flow/congestion control. UDP provides
datagrams without those guarantees by itself. Applications may build additional mechanisms over
UDP. Not every IP packet contains a sequence number that allows a router to rebuild a file:
reconstruction belongs to the relevant endpoint protocol.

A BitTorrent example
BitTorrent divides a file into pieces that peers exchange. A swarm is the participating group. A
seed has the complete content and can upload pieces. A downloading peer may upload too; the
word “leecher” does not necessarily mean a malicious user. Trackers can help peers discover one
another, while distributed discovery is also possible.
Security is part of the choice
A protocol name alone may not guarantee confidentiality or authenticity. Use protected versions
or secure alternatives where appropriate. File-transfer tools such as SFTP use a different protocol
from FTP. A networked application must also authenticate users and apply access controls at the
service.

Capacity is not responsiveness
Four problems to distinguish
Metric
What it tells you
Bandwidth / capacity
How much data a link can carry per second.
Throughput
The successful transfer rate actually achieved.
Latency
How long a transfer or response takes.
Jitter / loss
Variation in delay / missing packets.
Why a fast link can still feel slow
A wide road carries many cars, but a long journey still takes time. Similarly, high bandwidth does
not remove propagation delay, queueing or server processing. Retransmitting lost data can add
delay; interference and contention can reduce throughput. Measure the entire task, not just the
advertised link rate.
Choose a response to the problem
Compress or summarise data when capacity is limited. Reduce unnecessary round trips when
latency matters. Use timestamps to identify stale measurements. Buffering can smooth jitter for
playback, but adds delay. Redundancy and reconnect logic can improve resilience, while local
control keeps a time-critical action from depending on an unavailable remote link.

Protect data and its meaning
Three different goals
Goal
Question
Security
Who can access, change or disrupt the system?
Privacy
How is personal data collected, used and shared?
Integrity
Has the data remained correct and unaltered?
Validation versus verification
Validation checks whether an input meets rules: range, type, length or a valid calendar date. It
cannot prove a plausible value is true. Verification checks that data agrees with a source or
expected copy, such as double entry or a transfer checksum. Checksums detect some errors; a
cryptographic authentication mechanism is needed to resist deliberate modification by an
attacker.
Use layers of protection
Strong authentication, least-privilege access, updates, backups and network filtering address
different risks. Malware can damage or steal data; spyware monitors activity; phishing tricks a user;
pharming redirects a user to an unintended destination. A firewall is not a substitute for secure
software, and antivirus cannot promise to detect every threat.

From plaintext to ciphertext
Encryption uses an algorithm and a key to transform readable plaintext into ciphertext. Correctly
implemented cryptography can protect confidentiality, but key management and authentication
remain essential. Encryption alone does not prove who sent a message or ensure that a device
receiving it is trustworthy.
Two approaches
Symmetric
Asymmetric
Uses a shared secret key.

Secure protocols commonly use asymmetric mechanisms to authenticate or establish shared

Do not invent an encryption scheme by substituting characters or treating a checksum as a secret;

Trust, signatures & certificates
A signature protects authenticity and integrity
A sender signs a message, usually through a hash-based construction, using a private signing key.
A verifier checks the signature with the matching public key. A valid signature supports a claim
about the key used and whether the signed content changed. It does not encrypt the message or
prove that the message’s claims are true.
A simplified verification path
Message +
signature
Trusted public key
Verify
Accept or reject
Signing is not generally “encryption in reverse”; the operations depend on the signature algorithm.
Certificates and TLS
A digital certificate binds an identity, such as a domain name, to a public key and is signed by an
issuer. A client checks the trust chain, validity and expected name. TLS uses authentication and
cryptography to protect communication, including HTTPS. SSL is obsolete and should not be
deployed. A certificate can authenticate a domain without proving the site is honest in every other
respect.

Encryption modes & quantum ideas
Blocks and streams
A block cipher operates on fixed-size blocks; a mode specifies how it is used for longer messages.
A stream cipher combines data with a generated keystream. Reusing a key/nonce combination
incorrectly can undermine security. Authenticated encryption also detects unauthorised changes,
rather than providing confidentiality alone.
Understand CBC as a historical example
Cipher block chaining combines a plaintext block with the previous ciphertext block before
encryption, starting with an initialisation vector. Correct IV handling, padding and authentication
matter. CBC is useful to understand, but a new application should use a vetted protocol and
suitable authenticated-encryption construction rather than assembling its own cryptographic
workflow.
What quantum key distribution does
QKD uses quantum signals and classical communication to establish key material. Its security
analysis detects disturbance statistically under stated assumptions; it does not make every device
or message unhackable. It requires specialised infrastructure and authenticated classical
communication. Post-quantum cryptography is a different approach: algorithms designed to resist
quantum attacks on conventional computers.
