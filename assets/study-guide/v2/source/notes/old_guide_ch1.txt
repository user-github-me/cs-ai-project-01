From bits to bytes
Two states, many meanings
A bit is a binary digit: 0 or 1. Electronic circuits distinguish two ranges of voltage, allowing
hardware to store and process bits reliably. Eight bits form one byte. A word is the group of bits a
processor handles as a unit; its size depends on the architecture. The same pattern may represent
a number, a character or an instruction: the interpretation supplies the meaning.

Units matter
Lowercase b means bit; uppercase B means byte. Divide bits by 8 to obtain bytes. Decimal
prefixes use powers of ten; binary prefixes use powers of two. For example, 2 KiB = 2 × 1,024 =
2,048 bytes. A network speed in Mb/s is not the same unit as a file size in MB.

Binary, denary & hex
Place value does the work
Denary uses powers of 10. Binary uses powers of 2, so the positions in an eight-bit number are
128, 64, 32, 16, 8, 4, 2 and 1. Add the positions containing 1: 00101101 = 32 + 8 + 4 + 1 = 45. To
convert denary to binary, select those powers of two, or repeatedly divide by 2 and read the
remainders backwards.

Why engineers use hexadecimal
Group binary digits in fours from the right: 0010 1101 becomes 2D. Hexadecimal is a compact
notation for the same value, useful in memory dumps, colour codes and hardware addresses.
Binary addition carries when a column reaches 2: 1 + 1 = 10. With a fixed width, check whether a
carry or signed overflow changes the interpretation.

Read two’s complement
The leftmost bit has a negative weight. In eight bits, 11111011 means −128 + 64 + 32 + 16 + 8 +
2 + 1 = −5. In n bits, the range is −2^(n−1) to 2^(n−1) − 1. Always state the width: a bit pattern
has no unique signed meaning without a representation and a width.
Subtract by adding the negative
To calculate 9 − 3 in eight bits, add 00001001 to the two’s complement of 00000011: 11111101.
Keep the eight result bits, giving 00000110. A carry outside the width is discarded. Signed
overflow occurs when the true result lies outside the representable range; it is not the same as an
unsigned carry.

Numbers, characters & codes
BCD stores one decimal digit at a time
Binary-coded decimal allocates four bits to each decimal digit. Decimal 259 becomes 0010 0101
1001. This is different from converting the whole number 259 to ordinary binary. Patterns
1010–1111 are unused as decimal digits in ordinary BCD. Decimal representations are useful
where exact decimal digits matter, including displays and some financial calculations.
Characters need an agreed code
A character set defines the available characters. An encoding maps characters to stored values.
ASCII defines 128 codes, covering English letters, digits, punctuation and control characters.
Unicode assigns code points to characters from many writing systems. UTF-8 and UTF-16 are ways
to encode those code points; Unicode does not mean every character occupies the same number
of bytes.

Build a digital image
Pixels and colour depth
A bitmap is a grid of pixels. Pixel dimensions describe its width and height; resolution may also
describe pixel density when an image is displayed or printed. Colour depth is the number of bits
used per pixel. With b bits per pixel, up to 2^b different codes are available. More pixels preserve
finer spatial detail; more bits per pixel allow more colour or intensity values.

Bitmap versus vector
A vector image stores shapes, paths and their properties. It can scale without pixelation, making it
useful for diagrams and logos. Photographs are normally bitmaps. The size formula above
excludes headers, palettes, metadata and compression; an actual file may have a different size.

Sample, store & compress
Turn an analogue wave into numbers
An analogue-to-digital converter samples a sound signal. Sampling rate is the number of samples
per second, in hertz. Sampling resolution, or bit depth, is the number of bits per sample. A higher
rate can represent a wider range of frequencies; a greater bit depth provides finer amplitude
steps. Both increase uncompressed storage requirements.
Estimate audio size
Uncompressed audio size in bits = sampling rate × bit depth × channels × duration. For 10
seconds of mono audio at 8,000 samples/s and 16 bits/sample: 8,000 × 16 × 1 × 10 = 1,280,000
bits, or 160,000 bytes. Stereo requires two channels.

The stored-program computer
Instructions and data share memory
In the introductory Von Neumann model, memory holds both instructions and data. The CPU
fetches instructions, decodes them and performs the required operations. The arithmetic logic
unit (ALU) performs calculations and comparisons. The control unit coordinates the operation of
the CPU, memory and input/output devices. Registers hold small amounts of immediately needed
information.
The main connections
CPU
System buses
Memory / I/O
Address bus: identifies a location. Data bus: carries instructions or values. Control bus: carries signals such as
read and write.
Timing and the bottleneck
The system clock coordinates operations. A clock frequency of 3 GHz means three billion clock
cycles per second, not necessarily three billion completed instructions. Cache and pipelining
reduce some delays, but moving instructions and data through shared resources can still restrict
throughput. Real processors extend this simplified model in many ways.

Give each register a job
PC is the program counter: the next instruction address. MAR identifies the memory location
being accessed. MDR holds data moving to or from memory. CIR holds the current instruction.
ACC is an accumulator for intermediate arithmetic results in this teaching model. A branch
instruction may replace the normal next value of PC.
A useful analogy
Think of a recipe: PC marks the next recipe line, MAR selects its location, MDR carries the line, CIR
holds the instruction being followed, and ACC is a temporary mixing bowl. In this simplified
one-word instruction model PC advances by 1; actual instruction sizes and timing depend on the
processor.

Choose the right level
Machine code contains the instructions a processor executes. Assembly exposes
architecture-specific operations and registers. High-level languages offer abstractions such as
variables, functions and data structures. They improve portability, but some translation or runtime
support is still needed. A language may have both compiled and interpreted implementations.
Trade-offs are implementation-dependent
Ahead-of-time compilation can support fast execution and catch some errors before running.
Interpretation can support rapid experimentation and interactive debugging. Many modern
systems combine compilation, interpretation and just-in-time compilation. It is too simple to say
that all interpreters translate one source line at a time or that all compilers produce a standalone
executable.

Two passes and a helpful editor
A two-pass assembler first builds a table connecting labels to addresses, then uses it to resolve
operands and encode instructions. An integrated development environment (IDE) combines
editing, syntax highlighting, completion, translation and debugging. Breakpoints and
single-stepping let you inspect the changing PC, registers and memory.

The operating system’s jobs
Coordinate shared resources
Management task
Purpose
Processes
Schedule CPU time and coordinate running programs.
Memory
Allocate and protect memory; manage virtual memory.
Devices and files
Use drivers, organise storage and provide I/O services.
Security
Authenticate users and enforce access permissions.
Utilities support maintenance
Backup software creates recoverable copies; test restoration as well as copying. Antivirus checks
for known and suspicious malware activity. A formatter prepares a file system and may destroy
access to existing data. Repair tools check file-system structures. Compression tools reduce
storage or transfer size. Defragmentation helps some hard disks; it is not routine maintenance for
SSDs.
Software does not replace hardware
The OS provides a managed interface to physical resources. A program still needs CPU time,
working memory and access to its files. Good resource management improves sharing and
responsiveness, but it does not remove limits in memory capacity, processing speed or storage
performance.

Events, interrupts & peripherals
Respond without checking everything constantly
An interrupt requests the processor’s attention. For an enabled interrupt, the processor and
operating system preserve the required execution state, transfer control to an interrupt service
routine, then restore state and resume. Exact timing and saved registers depend on the
architecture. Not every request is handled immediately; priorities and masking affect when it is
serviced.
